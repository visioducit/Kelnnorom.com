The Implementation sequence
Do not paste and implement the entire prompt at once and generate the entire site in one uncontrolled pass. 


The work flow is to finish each of the underlisted items below, audit and test to find and fix what’s not perfect,  present each line item as a phase for approval and wait for authorization to proceed to the next line item.


Architecture pass — generate the routes, content schemas, design tokens, global layout and component tree.
Visual foundation pass — build typography, navigation, buttons, theme system, grid and responsive primitives.
Homepage pass — hero → system map → metrics → career narrative → case studies.
Evidence pass — build the case-study engine, timeline and Operating Stack from structured data.
Inner-page pass — Work, Experience, Capabilities, About, Insights, Contact and Executive Brief.
Polish pass — motion, responsive recomposition, accessibility, SEO, loading/error states and performance.
Factual audit — compare every employer, date, metric, title and claim against the authoritative source material before deployment.
One particularly important implementation decision: keep the content completely separate from the components. Kel's career is likely to evolve, and this architecture means adding a new engagement, case study, insight or achievement should be a data/content change—not a redesign.
The strongest version of this site isn't ultimately a portfolio with clever visuals. It's a visual argument: the breadth of Kel's career is precisely what gives him the ability to see connections other specialists miss.
